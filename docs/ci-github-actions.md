# Continuous Integration & GitHub Actions

StateBreak integrates natively into CI/CD pipelines to catch state-handling regressions in agent PRs before deployment.

## GitHub Actions Workflow Example

Create `.github/workflows/statebreak.yml`:

```yaml
name: Agent Failure Laboratory

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test-agent-resilience:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install StateBreak
        run: |
          pip install --upgrade pip
          pip install .

      - name: Run StateBreak Failure Suite
        run: |
          statebreak run scenarios/ --agent guarded --format sarif -o statebreak-results.sarif

      - name: Upload SARIF to GitHub Code Scanning
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: statebreak-results.sarif
          category: statebreak-agent-eval
```

## SARIF 2.1.0 Support

When invoked with `--format sarif`, StateBreak outputs standard SARIF 2.1.0 results. Any blocking finding generated by an oracle appears directly on the GitHub Pull Request diff as a security or reliability warning with exact remediation guidance.
